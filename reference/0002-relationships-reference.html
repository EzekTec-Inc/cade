Relationships, Technology Tags & Semantic Direction

Relationship Syntax

<sourceIdentifier> -> <destinationIdentifier> [description] [technology] [tags]

Best Practice Conventions

Component Example Guidance
Direction (->) app -> database Direction of dependency or invocation, never return payload.
Description "Queries account records using" Active verb phrase answering: What business task is being initiated?
Technology "SQL / TCP 5432" Protocol, serialization, or network port.
Tags "Sync, Core" Used for custom line styling (colors, dashed lines, animations).

Common Anti-Patterns to Avoid

  • The "Data Flow" Arrow: Pointing the arrow from a server back to a client because "data is being sent back". The arrow should point to the system being called.
  • Empty Descriptions: a -> b with no text. Every relationship in a landscape model must explain the functional reason for the connection.
  • Generic "Uses": Writing "Uses" instead of specifying the action (e.g. "Sends payment instructions to").
