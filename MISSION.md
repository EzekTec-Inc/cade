# Learning Mission: System Landscape Architecture with Structurizr DSL

## Mission Statement
Master **Structurizr DSL** from first principles to design, document, and communicate high-level **System Landscape**, **Reference**, and **Logical Architectures** using the C4 model and Architecture-as-Code.

## Why This Matters
Modern enterprise systems and distributed platforms are too complex for static whiteboard sketches or disconnected Visio/Draw.io boxes. By treating architecture as code through Structurizr DSL:
1. **Single Source of Truth**: One coherent model defines all systems, people, and relationships; views are simply dynamic projections of that model.
2. **Cross-System Clarity**: Clearly define enterprise boundaries, third-party integrations, customer personas, and internal platforms.
3. **Automated Governance**: Architecture diagrams can be version-controlled in Git, tested in CI pipelines, and rendered consistently without manual repositioning toil.

## Current Baseline
- **Learner Profile**: Complete beginner to C4 modeling and Structurizr DSL syntax.
- **Focus**: Starting from fundamental concepts (workspace, model, views) progressing directly toward enterprise system landscape authoring.

## Milestones
- [x] **Milestone 1: The Core Mental Model** — Understand the separation of *Model* vs *Views*, workspace syntax, Person, and SoftwareSystem definitions.
- [x] **Milestone 2: Relationships & Semantics** — Model unidirectional and bidirectional flows with clear descriptions and technology tags.
- [x] **Milestone 3: The System Landscape View** — Master `systemLandscape` views, enterprise boundaries, groups, and auto-layout rules.
- [x] **Milestone 4: Styling, Themes & Export** — Apply C4 color schemes, shapes, tags, and export to Mermaid, PlantUML, and interactive HTML.
- [x] **Milestone 5: Modular Architectures** — Use `!include`, `!extend`, and reference patterns for scalable multi-repository architecture models.
