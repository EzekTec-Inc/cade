Lesson 0003 · Milestone 3: Landscape Views

Enterprise Boundaries, Groups & The System Landscape View

Now that you know how to declare elements and connect them with clear protocols, we arrive at the heart of your mission: Enterprise System Landscape Architecture.

A landscape view answers the highest-level question in enterprise architecture: "What systems does our organization own, who uses them, and what third-party services do we depend on?"

1. The `enterprise` Boundary

In a real enterprise, some systems are owned and operated internally, while others belong to external SaaS providers, banks, or regulatory partners. Structurizr DSL gives you the enterprise block to draw this boundary: 

workspace "Global Retail Enterprise" {
    model {
        customer = person "Shopper" "Retail consumer placing orders"

        // Everything inside here is owned by your organization
        enterprise "Acme Corporation" {
            storefront = softwareSystem "E-Commerce Storefront" "Public shopping portal"
            inventory = softwareSystem "Inventory System" "Tracks warehouse stock"
        }

        // External systems defined OUTSIDE the enterprise block
        stripe = softwareSystem "Stripe Payment Gateway" "Third-party payment processor"
        fedex = softwareSystem "FedEx Logistics API" "Third-party courier and shipping tracking"

        // Cross-boundary connections
        customer -> storefront "Browses products and places orders using" "HTTPS"
        storefront -> stripe "Authorizes credit card charges with" "REST / HTTPS"
        storefront -> inventory "Reserves purchased stock in" "gRPC"
        inventory -> fedex "Schedules parcel pickup via" "HTTPS / JSON"
    }

    views {
        systemLandscape "landscape" "Enterprise Landscape Overview" {
            include *
            autoLayout lr
        }
        theme default
    }
}

2. Grouping Systems by Domain with `group`

As an enterprise grows from 5 systems to 50, a flat list becomes unreadable. You can organize systems into logical domains using group blocks inside the enterprise: 

enterprise "Acme Corporation" {
    group "Commerce & Sales" {
        storefront = softwareSystem "Storefront"
        pos = softwareSystem "In-Store POS"
    }

    group "Supply Chain & Fulfillment" {
        inventory = softwareSystem "Inventory Management"
        warehouse = softwareSystem "Warehouse Ops"
    }
}

3. The `systemLandscape` View Block

Unlike a `systemContext` view (which focuses on only one system and its neighbors), a systemLandscape view shows the entire enterprise forest:

  • include *: Pulls in all people, enterprise systems, and external systems.
  • include <element>: Selectively includes specific systems to focus on a particular capability domain.
  • autoLayout lr: Renders elements from Left-to-Right (or tb for Top-to-Bottom).
